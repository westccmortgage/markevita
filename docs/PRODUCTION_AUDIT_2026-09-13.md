# Аудит производства MarkeVita — 13 сентября 2026

Проверена цепочка от настроек и сценария до выдачи готового эпизода, а также продолжение после отказа провайдера, сетевого сбоя и потери рабочего контейнера. Исправления проверяются без реальных платных запросов. Это аудит кода и тестов, а не подтверждение доступа всех рабочих ключей.

## Ограничения, которые остаются видимыми

1. **Причина рабочего fal.ai HTTP 403 не установлена.** Баланс на скриншоте положительный, scope API подходит для генерации. Это не доказывает, что в Render установлен тот же ключ и что у него открыт нужный endpoint. Исправление checkpoint устраняет ложную блокировку продолжения, но не меняет разрешения fal.ai.
2. **Неопределённый платный запрос нельзя безопасно повторить автоматически.** При сохранённом request ID можно получить результат. При потерянном ID или прерванном синхронном запросе Anthropic/ElevenLabs требуется сверка с провайдером. Интерфейса для полной такой сверки пока нет; приложение сообщает об этом до новых платных этапов. Старые записи без доказательства отказа не очищаются.
3. **Изменение уже запущенного сценария и лимита бюджета — отдельная операция.** Продолжение проверяет исходную версию. Существующая функция `record_override` пишет запись локально и не меняет live-бюджет в R2: её нельзя считать рабочим способом увеличить бюджет активного эпизода. Текущий лимит в этом выпуске не увеличивался.
4. **Seedance не подключён.** Изменения одного `FAL_VIDEO_MODEL` недостаточно: текущий адаптер и расчёт цены относятся к Veo. Для Seedance нужны отдельные параметры, цена и проверка одной сцены с теми же персонажами. OpenAI остаётся дополнительной интеграцией, а не автоматически включённой заменой режиссёра или QC.
5. **Нет гарантии отсутствия новых внешних ошибок.** Проверяемые локально причины теперь обнаруживаются раньше. Отказ аккаунта, очередь, недоступность сервиса, модерация конкретного кадра и качество результата остаются событиями реального запуска.

## Дополнение: новый ключ fal.ai и HTTP 401

Новая задача в 22:20 UTC дошла до отправки запроса и получила HTTP 401. Журнал в 22:17 UTC подтверждает перезапуск приложения. Строка `configuration OK` проверяет основные настройки Studio, но не авторизацию fal.ai. Уровень ключа API подходит для используемых публичных моделей.

Добавлены общая проверка формата FAL_KEY и удаление случайных пробелов по краям. Префиксы заголовков, кавычки, маскированные и неполные значения `key_id:key_secret` выявляются до резервирования бюджета. Правильный формат сам по себе не подтверждает доступ. Страница «Интеграции» и журнал запуска показывают первые восемь символов публичного UUID ключа, чтобы сравнить с записью в fal.ai. Секретная часть не выводится; рабочий ключ в ходе аудита не просматривался.

При `STUDIO_ALLOW_CONNECTION_TESTS=true` кнопка «Тест» проверяет fal.ai через GET `/v1/models/pricing`: это служебный API с обязательной авторизацией ключом уровня API. Запрос не запускает генерацию и не меняет тарифы или выбранные модели. Перенаправления отключены; тексты ответов провайдера не выводятся. Успех означает авторизацию в служебном API, а не гарантированный доступ к генерации каждой модели. Результат сбрасывается после перезапуска или изменения любой части ключа. Миграция базы не нужна. Если сетевые проверки отключены, интерфейс явно сообщает об этом.

Источники: [формат полного ключа](https://fal.ai/docs/platform-apis/v1/keys/create), [служебный API цен](https://fal.ai/docs/platform-apis/v1/models/pricing), [авторизация и уровни доступа](https://fal.ai/docs/api-reference/platform-apis/authentication).

Действительность рабочего ключа ещё не подтверждена: управление Studio заблокировано проверкой доступа в этой сессии. Реальная генерация в ходе проверки не запускалась.
